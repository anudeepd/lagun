# Releasing Lagun

Releases are created from **Actions → Release → Run workflow** on the `main` branch. Choose a semantic version bump (`patch`, `minor`, or `major`) and leave **publish** unchecked for a preview. Preview runs validate the current synchronized version, run all backend and frontend checks, build and smoke-test the wheel and source distribution, then retain the tested files as the `lagun-dist` workflow artifact; they do not commit, tag, create a GitHub Release, or publish to PyPI.

For a release, select **publish** and the intended bump. The workflow calculates the next version from `pyproject.toml`, verifies that the corresponding `v<version>` tag is unused, synchronizes the Python, npm, npm lock, and uv lock versions, and builds and validates both distributions. After all checks succeed it commits the version files to `main`, creates the GitHub Release with the exact tested distribution artifacts, and publishes those artifacts to PyPI through GitHub OIDC. The `pypi` GitHub environment is already configured as the PyPI Trusted Publisher for `anudeepd/lagun` and this `release.yml` workflow; no API token is used.

The release checks require `uv sync --extra dev --extra ldap`, `uv lock --check`, Ruff, backend tests, frontend npm lint/tests/build, generated license notices, a freshness check of both committed frontend output locations, and the `e2e` Playwright suite against an isolated MySQL 8 service (with Chromium and Firefox installed). Before dispatching a real release, merge the desired code and changelog updates to `main`, ensure the committed frontend bundle and notices are current, and confirm the run has permission to push the version commit to `main`.
